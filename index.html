Projects

Latprobe

Python · Linux · diagnostics
  • Most Linux performance tools are tool-driven, you have to already know which knob shows what. Latprobe flips that: you say what you care about (“network jitter”) and it runs the right battery of checks.
  • 42 checks across 9 profiles (CPU governor, C-states, SMT, NIC drops, IRQ affinity, NUMA, clocksource, hugepages), each scored OK / WARN / FAIL with raw evidence and a concrete fix.
  • Cron-safe by default, with one opt-in disruptive cyclictest probe; RPM-packaged for RHEL, Amazon Linux, and Ubuntu with JSON alert integration.
  • Turns “the box feels jittery” into a ranked list of causes and fixes in a single command.

HFT-style low-latency stack on AWS bare metal

Linux · DPDK · ENA · c6in.metal
  • Tested the common belief that you can’t get HFT-grade low latency in the cloud without a Solarflare kernel-bypass NIC.
  • On c6in.metal: core isolation (isolcpus / nohz_full / rcu_nocbs), idle=poll with C-states capped, SMT siblings offlined, IRQs steered to housekeeping cores, and 1 GiB hugepages.
  • Proved out DPDK kernel bypass through the ENA Poll Mode Driver, busy-poll run-to-completion on an isolated core.
  • Worst-case scheduling jitter dropped from 138 µs to 7 µs (~20× tighter tail), measured with open tools and fully documented.

udplat — UDP latency measurement tool

Python · networking · diagnostics
  • Zero-dependency Python tool that measures UDP round-trip latency and reports the percentiles that matter, p50 / p99 / p99.9 / max, not the average. JSON output and a p99 threshold exit code for automation and alerting.
  • Closed-loop ping-pong design, with busy-poll and CPU-pinning options and packet-loss tracking.
  • Tested on two AWS c6in.metal boxes in a cluster placement group: real same-rack wire RTT of p50 35.9 µs, p99 38.7 µs, 0% loss across 300,000 packets (busy-poll + CPU pinning).
  • Finding: busy-poll only pays off when the thread is pinned, unpinned it was slightly worse than a plain blocking socket.

Things I believe about performance

  • The average is a comforting lie. Measure p99.9 and max, or you’re measuring nothing.
  • Deep C-states are the number-one source of microsecond jitter nobody looks at.
  • A perfectly pinned thread reading remote-node memory still pays the NUMA tax.
  • Don’t tune from theory. Read the current value first, change one thing, then re-measure.
  • If a result has no reproducible measurement behind it, it’s an opinion, not a finding.
